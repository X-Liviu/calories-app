Asunto: Contexto del Proyecto "TrackBites" (App Fullstack de Seguimiento de Calorías)

Hola, necesito tu ayuda para desarrollar/mejorar mi aplicación llamada TrackBites. A continuación, te proporciono el contexto técnico y funcional completo para que entiendas la lógica de negocio antes de empezar:

1. Resumen del Proyecto:
Es una aplicación web fullstack diseñada para el registro histórico y recuento de calorías. Permite a los usuarios gestionar su ingesta diaria a través de una estructura jerárquica de tiempo y comidas.

2. Arquitectura del Proyecto

Estructura: NPM Monorepo dividido en tres directorios principales:
/frontend (Cliente)
/backend (API)
/e2e (Tests End-to-End)

3. Stack Tecnológico y Estrategia de Testing

Frontend (/frontend):
Core: React, Redux & Redux Thunk, React Router DOM, Vite, Axios.
Testing: Vitest (runner), JSDOM (ambiente) y React Testing Library.

Backend (/backend):
Core: Node.js, Express, JWT, Bcrypt.
Base de Datos: MongoDB Atlas + Mongoose.
Testing: Jest + Supertest.

End-to-End (/e2e):
Herramienta: Playwright.

4. Lógica de Negocio y Funcionalidades Principales:

A. Autenticación y Gestión de Usuario:
Registro e Inicio de Sesión (Login/Register).
Gestión de perfil: Modificación de datos personales y eliminación de cuenta (borrado completo).
Seguridad: Rutas protegidas que requieren sesión activa.

B. Funcionalidad Núcleo: 
El Catálogo Personal

El usuario dispone de un "banco de alimentos" propio.
CRUD: Puede Crear, Leer, Actualizar y Borrar alimentos en este catálogo.
Objetivo: Facilitar la inserción rápida de alimentos frecuentes en las comidas sin tener que reescribir sus macros cada vez.

C. Funcionalidad Núcleo:
El Tracker (Jerarquía de Datos) La estructura de datos sigue esta jerarquía estricta:

Semanas: El usuario crea/borra semanas.
Días: Dentro de una semana, existen 7 días (se pueden crear/borrar lógica de visualización).
Comidas: Dentro de cada día, se añaden/borran "momentos" de comida (ej. Desayuno, Almuerzo).
Alimentos (Items): Dentro de una comida, se registran los alimentos consumidos.

D. Flexibilidad en el Registro de Alimentos Al añadir un alimento a una comida, el usuario tiene dos vías:

Desde el Catálogo: Seleccionar un alimento ya guardado (carga rápida).

Alimento "Ad-hoc" (Personalizado): Crear un alimento directamente en la comida (nombre y calorías) sin necesidad de guardarlo previamente en el catálogo global.

Permite modificar o borrar alimentos ya registrados dentro de una comida específica.

E. Navegación y Análisis

Filtro por Años: Visualización de semanas organizadas por año.

Buscador: Capacidad de filtrar y encontrar una semana específica rápidamente.

5. DevOps y CI/CD
Pipeline: Utilizo GitHub Actions configurado en pipeline.yml.
Flujo de Verificación:
Lint: Verificación de estilo.
Tests Unitarios/Integración: Ejecución en paralelo de test_backend y test_frontend.
Tests E2E: Se ejecutan solo si los anteriores pasan.
